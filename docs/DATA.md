# Data

Every dataset used by privgate is listed here with its source, pinned revision and license.
**Both datasets are fully SYNTHETIC**: the text, the people, the organisations and every
identifier were generated by language-model pipelines; no record describes a real person.
The raw files are downloaded into `data/raw/` (gitignored) and are **not redistributed** by
this repository. Only derived metadata is committed: `data/manifest.json` (file sizes,
SHA-256 hashes, evaluation-set hashes) and `results/data_stats.json`.

Every number on this page is generated by a script (blocks between `<!-- name:begin -->` and
`<!-- name:end -->` markers, written by `scripts/data_stats.py`); prose contains no measured
values.

Reproduce:

```
pip install -e ".[dev,data]"
python scripts/download_data.py     # pinned files -> data/raw/, hashes -> data/manifest.json
python scripts/inspect_data.py      # schema findings below (read-only)
python scripts/build_eval_sets.py   # data/processed/*.jsonl, hashes -> data/manifest.json
python scripts/data_stats.py        # results/data_stats.json and the tables on this page
pytest -q -m data                   # integration tests on the real files
```

## Schema findings

Found by `scripts/inspect_data.py` on the pinned files; the unit-test fixtures in
`tests/parquet_fixtures.py` reproduce these schemas exactly, and
`tests/test_data_integration.py` checks the fixtures against the real files.

**Nemotron-PII** (train and test files have the same schema). All nine columns are Arrow
`string`: `uid, domain, document_type, document_description, document_format, locale, text,
spans, text_tagged`.

- `spans` is a **string**, not a list column. It holds a list of
  `{"start", "end", "text", "label"}` dicts written as a **Python literal** (single quotes) in
  almost every row and as JSON in a handful of rows. It is parsed with `json.loads`, falling
  back to `ast.literal_eval` (literals only, never executes code).
- Offsets are character offsets into `text`, end exclusive, and every span stores the
  covered `text`, so offsets can be verified. The stored text is occasionally an integer
  (ages, CVVs) and is compared as a string.
- **Each `uid` occurs exactly twice per file**, once with `locale="us"` and once with
  `locale="intl"`: two renderings of one generated persona and document type, with different
  text but shared attributes (same domain, often the same date of birth). privgate's
  `doc_id` is therefore `nemotron:<uid>:<locale>`, and `meta["group_id"]` keeps the uid.
  Train and test files share no uid.
- **The train and test files cover almost disjoint sets of `domain` values** (facts table
  below): the test file is a domain-shifted split of the same generator, not an i.i.d.
  sample. Our dev split is drawn from the train file and is therefore in-domain.
- The dataset card describes 100,000 records split 50k/50k and `spans` as
  `List[{start, end, label}]`; the pinned files differ (each file has the row counts in the
  table below, and spans are a string with a `text` key). We follow the files.

**Gretel English test file.** Columns: `document_type, document_description, expanded_type,
expanded_description, language, language_description, domain, generated_text, pii_spans`
(`string`); `conformance_score, quality_score, toxicity_score, bias_score,
groundedness_score` (`int64`); `pii_types` (`list<string>`); `pii_type_labels`
(`list<int64>`); `__index_level_0__` (`int64`, a pandas index, unique, used as `doc_id`
`gretel:<index>`).

- `pii_spans` is a **JSON string** with a list of `{"start", "end", "label"}` dicts; no
  covered text is stored, so offset verification can only check bounds.
- `pii_types` repeats the labels of `pii_spans` in order; it is not used.
- The card's metadata describes `train`/`test` files and mixed languages; the pinned file
  is English only and has a single domain value (`finance`).

## Annotation conventions

From the dataset cards and from inspection:

- **Nemotron-PII.** Labels were produced together with the generated text ("synthetic
  labelling"), not by human annotators. Person names are split into `first_name` and
  `last_name` spans. The stored span text is sometimes **case-normalised** while the offsets
  are correct (e.g. stored `white` where the text says `White`, stored `Ann` for `ANN`);
  this concerns mostly attribute labels such as `race_ethnicity`, `education_level` and
  `political_view`. A few spans cover template blanks (`_______`). Locale `intl` documents
  follow international conventions, with some U.S.-style overlap according to the card.
- **Gretel.** Spans were located after generation and double-checked with the GLiNER NER
  library; records were filtered by an LLM-as-a-judge and spot-checked by humans. The card
  warns that missed or wrong labels remain. Tag names follow the Python `Faker` providers;
  `name` is a full name, `first_name`/`last_name` also occur. Overlapping duplicate spans
  occur (e.g. a company name and its prefix both labelled `company`).

Borderline decisions:

- `ID_NUMBER` holds identifiers issued to one person or to their account or record:
  government ids, tax ids, medical record and health-plan numbers, customer and employee ids,
  bank account numbers (incl. `bban`), licence and certificate numbers, licence plates,
  vehicle identifiers, biometric-record ids and generic `unique_id`.
- `OTHER` holds everything that is sensitive but has no dedicated type: personal attributes
  (age, gender, sexuality, ethnicity, religion, political view, blood type, language,
  occupation, education, employment status), credentials (password, PIN, CVV, API key),
  identifiers of institutions rather than people (bank routing number, SWIFT/BIC), technical
  identifiers (MAC address, device id, HTTP cookie), user names, and times of day (a time
  alone is not a date).
- `credit_card_security_code`/`cvv` are card data but not card numbers, so not
  `CREDIT_CARD`; `coordinate`/`local_latlng` are `LOCATION`.

## Normalisation

All loaders send every gold span through one pipeline (`privgate.data.documents`), in this
order; each step is configurable through `LoadOptions` and every change is counted in the
`LoadReport`:

1. **Label mapping** (above). `strict_labels=False` by default.
2. **Bounds check**: offsets must be integers with `0 <= start < end <= len(text)`; other
   spans are dropped (`out_of_bounds`).
3. **Offset verification**: if the dataset stores the covered text, `text[start:end]` must
   equal it. `offset_check="casefold"` (default) accepts a difference in letter case only and
   counts it (`case_only_mismatches`); `offset_check="exact"` drops those spans too. Any other
   difference drops the span (`offset_mismatch`). Why casefold: in Nemotron-PII every
   observed mismatch is a case difference with correct offsets, so dropping them would turn
   real PII into unlabelled text and penalise detectors that find it.
4. **Trimming** of surrounding whitespace (`spans_trimmed`); a span that is only whitespace
   is dropped (`empty_after_trim`).
5. **Overlaps**: overlapping gold pairs are counted (`overlapping_pairs`). With
   `overlap_policy="resolve"` (default) they are resolved by
   `privgate.spans.resolve_overlaps` (the longer span wins, then deterministic tie-breaks);
   removed spans are counted (`overlap`). `overlap_policy="keep"` keeps them all.
6. **`merge_adjacent`** (default ON): two spans with the SAME mapped label separated only by
   spaces or tabs are merged (`first_name "John"` + `last_name "Smith"` -> one PERSON
   `"John Smith"`), because detectors report a full name as one entity. A comma or any other
   character, a line break, or touching spans (no gap) block the merge. Line breaks block it
   because in these documents a line break between two names usually separates different
   entities (one person's surname at the end of a line, another's first name on the next).
   Merged-away spans are counted (`spans_merged`).

Bookkeeping identity, checked in tests: `spans_read = spans_kept + sum(spans_dropped) +
spans_merged`.

## Splits and evaluation sets

- **Split rule.** A Nemotron train-file document goes to **dev** iff
  `int(sha256(key), 16) % 100 < 10`, else to **train**; the Nemotron test file is **test**.
  `key` is `meta["group_id"]` (the uid) when present, else `doc_id`. Hashing the uid rather
  than the per-row `doc_id` keeps the `us` and `intl` renderings of a persona in the same
  split, so dev never contains near-copies of train documents. Gretel documents have no
  group and use `doc_id`.
- **Sampling.** `sample(docs, n, seed)` sorts by `doc_id` (duplicates are rejected), then draws
  with `random.Random(seed).sample`; the result does not depend on input order.
- **Named evaluation sets** (`privgate.data.splits.EVALUATION_SETS`):
  - `nemotron_dev_2k = sample(dev, 2000, seed=0)`: in-distribution development set;
  - `nemotron_test_5k = sample(test, 5000, seed=0)`: held-out test set from the same
    generator, but the Nemotron test file covers almost entirely different domains than the
    train file (see the facts table), so this set measures transfer to unseen domains;
  - `gretel_en_test` = every row of the Gretel English test file: out-of-distribution set.
- Each set is written by `scripts/build_eval_sets.py` to `data/processed/<name>.jsonl`
  (gitignored; one JSON object per line, UTF-8, LF line ends, sorted keys) and its SHA-256,
  size, recipe and load options are recorded in `data/manifest.json` under
  `"evaluation_sets"`. The integration tests rebuild the sets from the raw files and check
  that the hashes match.

## Known limitations

- **Synthetic text.** Generated documents are cleaner and more regular than real ones
  (formatting, spelling, entity density); detector scores on them may overestimate
  real-world performance.
- **English only, US-centric.** Nemotron personas are grounded in U.S. Census data (the
  `intl` locale still uses English); the Gretel set is the English file of a finance-only
  corpus. Formats from other countries are under-represented.
- **Domain shift inside Nemotron-PII.** Dev (from the train file) shares its domains with
  train; the test file uses other domains. Differences between dev and test scores mix
  domain transfer with ordinary sampling noise.
- **Label noise.** Nemotron labels come from the generator itself; Gretel labels come from
  an NER pass and LLM-as-a-judge filtering, which the card says can miss or mislabel PII. A
  detector's "false positive" may be an unlabelled real PII string.
- **Taxonomy compression.** Mapping the many raw labels of both datasets onto privgate's
  small set of types loses distinctions (e.g. all attributes become `OTHER`); per-type
  results must be read together with the mapping table.
- **Normalisation choices** (case-insensitive verification, overlap resolution, merging) shape
  the gold standard; all of them can be switched off through `LoadOptions` for sensitivity
  checks.
- **Near-duplicate renderings.** Nemotron's `us`/`intl` twins share attributes; the split keeps
  them together, but within one evaluation set both renderings of a persona can appear.
